# Qabas transcription engine

This directory contains Qabas's Python engine, copied from the universal-transcriber skill repository at commit `c1168da`. Qabas owns this copy and its tests independently. Runtime and tests require no skill checkout, skill instructions, mirror, installer, or skill release metadata. The app reports its own version and does not check for skill updates.

The scripts require Python 3.10 or later. Create the environment from this repository root:

```sh
python3 -m venv engine/.venv
engine/.venv/bin/python -m pip install -r engine/requirements.txt -r engine/requirements-dev.txt
pnpm run engine:test
pnpm run engine:lint
pnpm run engine:typecheck
```

On Windows, use `engine/.venv/Scripts/python.exe`. The root commands select that environment when present, otherwise `python3`. `engine:test` runs unittest discovery; the additional desktop cases use pytest (`engine/.venv/bin/python -m pytest engine/tests`). CI installs Poppler for the real PDF rendering cases, then runs both suites and the two static checks. NotebookLM, OCR, office conversion and media commands remain external dependencies; run `engine/.venv/bin/python engine/scripts/run_transcription.py --doctor` to inspect them. The optional Whisper backend needs the packages listed in [requirements.txt](requirements.txt).

Run the MCP server or apply the app's patch:

```sh
engine/.venv/bin/python engine/scripts/mcp_server.py --help
pnpm dsh --profile web --patch engine/transcriber.cordis.yml
```

Activate the environment before using the source profile so `python3` finds its dependencies. `TRANSCRIBER_ENGINE_ROOT` overrides this directory; `TRANSCRIBER_SKILL_ROOT` remains a legacy override. Student data defaults to the operating-system home plus `qabas/Qabas Library`, created with `modules/` on first use. `TRANSCRIBER_WORKSPACE` is a developer and test override. Saved workspace pointers and cwd do not select the library. Explicit `--workspace` remains available for developer CLI calls. [Host resolution](../packages/api/transcriber-engine/README.md) defines workspace selection and errors.

For the desktop sidecar, install [requirements-build.txt](requirements-build.txt), then run `pnpm run engine:build` (or `bash engine/build-engine.sh` from any directory). Build on the target OS and architecture. The script produces `engine/dist/transcriber-engine-<target-triple>[.exe]`; `TRANSCRIBER_DIST_DIR` and `TRANSCRIBER_PYINSTALLER_WORKDIR` override output directories. Desktop preparation copies the native sidecar and [MCP patch](transcriber.cordis.yml) into `runtime/app/engine/`, which Tauri includes through its existing runtime resource mapping. The binary contains the app version and runtime references. The build script verifies its help entry, MCP initialization version and packaged editorial reference before reporting success.

The runtime [editorial guide](references/drafting-and-editorial.md) and [grouping cases](references/lecture-grouping-cases.json) are the only copied skill references. Python and TypeScript tests read the same grouping JSON. Omitted test files are `test_anki_extraction.py` and `test_anki_generator.py` (the separate Anki skill), `test_next_version.py` (skill release machinery), and `test_version_checker.py` (skill updates and shared skill-version metadata). Their 75 unittest cases account for the difference from the source's 716 cases. The launcher-discovery tests instead pin the bundled sibling script and reject a missing bundled engine; student workspaces are never searched for engine code.

Subjects (مواد) are optional module metadata: `module.json` may hold an ordered `subjects` list of `{id, title, created, updated}` (slug ids; unique titles up to 120 characters), and a lecture definition may name one by `subject`. An unknown referent fails at load. `create_subject`, `rename_subject`, `reorder_subjects`, `delete_subject` and `set_lecture_subject` write under the registry lock; deleting a subject keeps its lectures, files and transcripts and clears their `subject` in the same write. `define_lecture` keeps a lecture's subject unless the request names one. Subjects never move files, change NotebookLM or affect a definition's transcript signature; listings report each manual lecture's `subject` and the module's `subjects`.

Lecture visibility is module-owned metadata. `module.json` stores safe recording names relative to `Lecture/` in `hidden_recordings`; `hidden_transcripts` retains the recording association for existing transcripts with legacy custom titles. `hide_lecture(module, title)` hides a defined or automatic unit and removes its manual definition atomically under the registry lock. A manual id disambiguates duplicate titles. `restore_recordings(module, recordings)` removes selected names from the hidden list without recreating definitions. Neither operation changes source files, NotebookLM sources or transcript files. Hidden recordings remain in file inventory with `hidden: true`, are excluded from unassigned organization sources, and cannot be used in a definition until restored. Fully hidden units and their orphan transcript rows are omitted from library listings; partially restored units contain only visible recording sources.

The MCP tools run without a chat through the Host registry Remotes. Direct source and packaged entry points also accept `run_transcription.py --workspace <workspace> --module <module> --hide-lecture <title>` or `--restore-recordings <name>...`; the sidecar uses its `run-transcription` subcommand with the same flags.

`remove_file` returns the retained `trash_path` and the entry `id` accepted by `restore_trash`. File placement and restoration remain engine-owned.

Reversible removal uses `remove_transcript(module, title, kinds)` with a non-empty subset of `final`, `draft`, and `verbatim`, plus `list_trash(module)` and `restore_trash(module, id)`. Selected outputs share one `.transcriber-cache/trash/<UTC timestamp>/` entry. Final removal includes figures, matching Anki outputs and the linked Index row; recordings, slides, definitions and NotebookLM remain untouched. Index edits are atomic and preserve remaining bytes. Matching run checkpoint directories move with the outputs and matching batch-ledger records are cleared so a new job cannot resume removed phases. Draft removal also archives its staged parts and validation metadata to prevent reuse of the removed text. Restoration puts them back, preserving unrelated later Index and batch changes. Destination conflicts refuse before any file moves.

`remove_module(module)` renames the entire module to `<workspace>/.qabas-trash/modules/<id>--<UTC timestamp>/`; `list_removed_modules()` lists archives and `restore_module(trash_id)` refuses a reused id. Results explicitly report `notebook_untouched: true`. Engine-held activity leases protect launcher and MCP operations, and removals refuse held module, lecture, batch or Index locks. Browser job records are client-local, so the guard cannot identify an idle chat between engine calls. Trash is never automatically purged. Legacy file trash and hidden recordings remain restorable; older hidden metadata uses its modification time when no original removal time was recorded. Lecture restoration unhides recordings without recreating manual definitions; new hide entries retain the original module metadata for history.

The same tools run through desktop Remotes without a chat. Direct CLI entries use `--remove-transcript <title> --transcript-kinds final draft`, `--list-trash`, `--restore-trash <id>`, `--remove-module <id>`, `--list-removed-modules`, and `--restore-module <trash-id>`. The sidecar's `run-transcription` subcommand uses those flags.

### Deterministic lecture jobs

`run_lecture_pipeline(module, lecture, mode, confirmed=true)` completes `transcribe`, `redo`, or `continue` without a chat model. The lecture button authorizes uploading its recordings, saving review and finalizing. The runner in [lecture_pipeline.py](scripts/lecture_pipeline.py) composes existing tool handlers: `begin_lecture` resolves the unit, uploads missing recordings, prepares the source manifest and exam index, extracts figures and fetches missing verbatims; `write_parts_with_agy` prepares the cached topic map, reads lecture evidence and questions, and writes missing parts; guide parts before the final guide part are written concurrently, up to the engine JSON `lecture_writer_workers` (default 3, integer of at least 1), and staged in part order with figure links already placed by an earlier part removed, while the final guide part and the questions part follow in order; `apply_review(from_parts=true)` saves the draft; `validate_draft` and `verify_provenance` check it; `finalize` commits the transcript and updates `Index.md`. Existing heading cleanup, figure extraction recovery, question deduplication and renumbering remain owned by those tools. The pipeline does not run a module-wide source sync or upload unrelated files.

MCP progress reports each preparation step, writing part and repair when `_meta.progressToken` is supplied. Every pipeline message starts with `<step>:`; only explicit `write_parts_with_agy: part N of M` checkpoints display writer-part progress in the tray. Other counts retain the step's own line. Request cancellation and the effort deadline stop owned subprocess trees and backoff waits; completed parts remain available. Continue reuses staged parts and saved drafts, including an interrupted redo beside its existing final transcript. Redo starts fresh by archiving that lecture's draft and stages under `.transcriber-cache/previous-drafts/`, even when a cached manifest records an earlier started redo; the existing final transcript stays until successful finalization. Internal retries preserve the new run's work. Continue restores segmentation budgets from valid `layout.json` and matching `parts.txt`; missing or inconsistent alignment moves stages under `.transcriber-cache/stale-staged/` and rebuilds repair parts from the saved draft, or rebuilds the guide from verbatim text. A read budget that cannot fit the current response limit is reset without refusing the lecture. Recovery resolves the cached unit manifest from module and lecture when begin has not returned its manifest. Changed saved bytes always require fresh validation and provenance checks.

Recovery in [pipeline_repair.py](scripts/pipeline_repair.py) escalates from deterministic cleanup to rewrites of affected parts, then smaller source slices staged in the same layout. Transient 5xx, overload, timeout, truncated-output and per-minute 429 errors retry with cancellable exponential backoff. Failed inputs are refreshed and unusable topic layouts retain recording-based repair text. Findings located in a part, and document-wide findings that name the parts to inspect, return to agy with the findings. Exhausting the repair rounds or recovery time starts validated salvage automatically, with time reserved for finalization. Salvage never replaces the explanation with recorded speech: if the Chronological Guide still fails validation, the run returns `failed` with the located guide findings followed by the most recent repair error as its `reason` and keeps the draft and staged parts for Continue. Ordinary validation and provenance checks remain mandatory; no validation finding is handed to chat.

`find_questions` ranks a lecture's indexed questions against its evidence (slides, verbatim text, material text): a question word scores its lecture frequency (sublinear) times its rarity in the module's bank, and option words count half. A question qualifies only when its stem matches the lecture's evidence, or the lecture title or assigned material names match it anywhere; the title match tolerates case, diacritics, y/i, doubled letters and one spelling edit (two from nine letters). Words in at least half of the module's defined lectures, or in more than 15% of the bank, are generic and score nothing, except that a title made only of common words still names its topic. A verified exam year multiplies the score by 1.5 rather than taking priority, so off-topic dated questions cannot displace on-topic ones. At most 50 entries are returned with `matched`, `returned` and `omitted` counts.

Sourced MCQs keep their paper's original two to six options, labelled consecutively from a; generated **[IMP]** MCQs use a–d. Lookup checks each cited paper independently and the paper-backed exam index; a cited name that is a paper's prepared text sidecar (`<original>.txt`) identifies that original paper. An uncertain secondary citation cannot erase a confirmed occurrence: repair removes unlocated citations, restores located sources and badges only evidenced years. If no cited paper confirms the question, lookup searches the other local assessment papers. An unlocated question retains its wording and options as **[IMP]**, with a provenance note rather than an invented year. An engine-issued receipt binds that exception to its original wording and ordered options; a model-written retention comment cannot grant it. Retention receipts are journaled before repaired drafts or parts are published, so interruption cannot turn original options into generated ones. Staged review boundaries include source-field changes.

Exam question occurrences distinguish `answer_status: printed`, `no_key`, and `unverified`. A missing official key leaves the answer null and does not require review; only recognized missing-key-only model reasons receive this exemption. Raw model advisories remain in `model_needs_review` and `model_review_reason`. Damaged or ungrounded parts, unsupported answer claims, ambiguous marks and unverifiable years retain review. Source `review_reasons` report paper-level year disagreements separately from the question review count. Merging a missing key with a printed answer does not create a conflict; conflicting printed answers do. Grounding accepts case- and digit-normalized alphanumeric text with whitespace removed: phrases under 20 characters require an exact match, and longer phrases require at least 95% similarity in an ordered source window. The token-based grounding path remains available for ordinary text. PDF inspection triggers OCR when more than 50% of at least ten non-empty lines are shorter than six characters, including alphabetic fragments that script-noise checks miss.

`build_exam_index` uses agy to extract questions from each supported original file. XLSX cells and DOCX paragraphs or table rows keep their source positions; other formats use the prepared page or line text. An XLSX worksheet whose first row names a question column (`Text`, `Question`, `Stem`), at least two option columns (`A`-`F`, `Option A`, `Choice A`) and an answer column (`Correct`, `Answer`, `Key`) is read by [spreadsheet_questions.py](scripts/spreadsheet_questions.py) without agy: each row becomes one question with its options, answer letter or option text, optional `Year`, `category`/`Topic`, `Explanation` and `No` cells, and passes the same grounding validation. Only rows whose answer cell names no option or whose year cell holds other than one exam year are flagged for review; an empty answer cell is an absent key. Those papers skip the automatic review and record `extractor: columns`; a batch that touches any other worksheet keeps agy extraction. The response must cover every input unit and cite source text for questions and options. A printed answer is kept only when its evidence matches the cited source; an unverifiable answer is omitted before automatic paper review. The engine validates each result against the original file hash and input-unit fingerprint, then publishes a schema-versioned index after each completed paper under the publication lock, rechecking all included sources. The engine JSON configuration sets `exam_index_batch_chars` (default 12000 source characters, excluding overlap) `exam_index_workers` (default 3 concurrent agy processes) and `exam_index_timeout_limit` (default 2); all require integers of at least 1. A capacity failure such as truncated output splits its batch, but a paper's extraction fails at its `exam_index_timeout_limit`-th agy timeout, and its automatic review fails at the same count while keeping the extraction. When one of a paper's batches fails, the paper's running agy processes stop. A signed-out agy fails its paper with cause `auth`, and every later batch that needs agy in the same build fails the same way without launching it; cached and column-read papers still complete. Source units remain indivisible, and neighbouring context retains five units on each side. Published question order follows source and batch order regardless of completion order. Validated per-file batches are saved in `.exam-index-state.json` with the configured budget, so cancellation or a later failure leaves finished work available for retry. A rebuild reuses an unchanged paper without rewriting that state or republishing the index for it, and reports only its final `done` progress when its batches and review are already saved. A changed budget invalidates that file’s batch cache; the prompt version remains unchanged, and cached raw responses are revalidated by current post-processing. Completed papers remain published after interruption, and an all-failed retry preserves the previous publication. The MCP tool's optional `papers` names the failed papers to retry; any other paper whose published failure still matches its file SHA-256 keeps that failure without preparation or extraction, while new, changed and cached papers are read as in a full build. Index entries merge matching questions across papers, while each file retains its full occurrence count and locations. `list_exam_questions` reads that saved file view in searchable pages without the lecture lookup's 50-question cap. Schema-1 parser indexes remain stale until rebuilt; their manual repairs are not carried because they have no source fingerprints. Later manual repairs carry only while the original and input-unit fingerprints match.

After extraction validation, [exam_question_review.py](scripts/exam_question_review.py) automatically reviews each agy-extracted paper before publication. It receives the validated questions and source-unit text. Image papers, unreadable PDFs and scanned PDFs (an image on most pages, detected with `pdfimages -list`) also supply bounded original page renders through agy's file reader, because a scan's text layer is OCR. Supported cleanup removes repeated question numbers, student marks, OCR debris and escaped quotes, normalizes option labels in printed order, and drops non-question fragments. Cleanup cannot introduce content words absent from the original extraction or cited units, except that a reading of the page renders may correct OCR misreadings in place: the corrected field must stay at least 75% similar character by character, and the OCR text is kept as `source_stem` or `source_options` for provenance. Other unsupported fields retain their original text. Source quotes and unit ids remain verbatim. Answers require an existing option and quoted source evidence or a recorded visible-page mark. `answer_status: uncertain` means the answer evidence could not be resolved; `no_key` means no answer key is available. Neither requires student review. Only genuine illegible or truncated source defects retain `needs_review` and a reason.

Review configuration accepts positive integers: `exam_review_batch_chars` defaults to 48000 (maximum 1000000), `exam_review_batch_questions` to 100 (maximum 20000), `exam_review_max_pages` to 30 (maximum 1000), `exam_review_image_max_size` to 2000 pixels (maximum 10000), and `exam_review_timeout_seconds` to 600 (maximum 3600). Oversized or capacity-failed batches split by question count. `.exam-index-state.json` caches review separately from extraction using the source-unit fingerprint, extracted-question hash, `REVIEW_PROMPT_VERSION`, and resolved settings. Successful responses are revalidated locally on reuse. Review failure publishes extracted questions with source `review_status: failed`; the next build retries only unfinished review. Successful review reports `done`. Structured progress includes `queued`, `reading`, `extracting`, `reviewing`, `done`, or `failed`, the paper filename, known question count, and extraction part counts while retaining the existing done/total/message fields.

`set_exam_year {module, path: "Questions/<original file>", year}` saves an owner-selected year from 1900 through 2100; null clears it. `Questions/.exam-year-overrides.json` stores a filename-to-year object independently of generated caches. The override applies to every paper occurrence immediately and on later builds, with `year_source: owner`; provenance verifies it against this store. Index post-processing retains the extracted year for clearing, without an agy call. Renaming moves the entry and trash retains it for restoration. Lecture lookups and Past Exams badges use the verified owner year. File inventory exposes effective `year`, `year_source` (`owner`, `paper`, `filename`, or null), and `review_status`; exam question pages expose the retained reviewed wording and options.


Dense question banks produce large structured question lists even from short source text; output size and generation time can limit a batch before the model's input capacity does. A timeout, output-limit/truncation error, unusable JSON response, or a response that skips required units bisects the required source units and schedules both halves in the same worker pool. Malformed proposal JSON gets the existing repair attempt before splitting. A unit counts as reviewed when `covered_unit_ids` lists it, even more than once, or an extracted question cites it. Splitting repeats down to one unit, with up to five context units on either side. For these capacity failures, only an unsuccessful single-unit leaf fails its paper; a page, paragraph or row remains indivisible. Progress reports the original part and each split half, such as `part 2 of 3 · split 1/2`. Saved split decisions and validated descendants let retries skip failed parent requests and reuse successful halves. Evidence-validation and authentication failures retain their ordinary per-file failure behavior.

Salvage protects Past Exams and Question Bank questions located in local papers or the paper-backed index, including papers omitted from the lecture manifest. It records used missing sources and attempts one bounded agy rewrite per invalid assessment. Rewrites must preserve sourced wording, clinical subquestions and MCQ options. If the answer or assessment format remains invalid, the transcript retains the evidenced question as a folded source excerpt with its original wording, options, subquestions and badge; the unvalidated answer is omitted and reported. Only unevidenced assessments still invalid after repair are dropped. Original stages are archived, retained sections are renumbered and the job note lists every dropped question. The [finish-always note patch](../engine-finish-always-notes.patch) records the rationale.

The last questions part is replaced when re-sent. Staging and review coalesce repeated assessment sections and remove exact repeated question blocks while retaining distinct wording, answers, options and source fields for validation. Guide bytes and staged recovery boundaries remain intact; repeating `apply_review(from_parts=true)` does not append assessments.

Publication and salvage require a Chronological Guide containing at least one alphabetic character outside headings, blockquotes, image links and HTML comments, plus a saved verbatim baseline containing alphabetic speech outside headings and blockquotes. Ordinary complete-document, coverage, editorial and provenance checks remain mandatory; the other four sections may be empty when no validated material is available. A headings-only scaffold without recorded speech cannot be saved by salvage or published. Failed recovery preserves draft/staged state, writes no transcript or index, and returns `status: failed`, the first failing `step`, the original `reason` and `findings`, a separate `salvage_error`, and `resume` module/manifest metadata when available.

Exam-index refresh runs once per lecture job, in the background while `begin_lecture` and the earlier guide parts run; the final guide part, the questions part, review and salvage wait for it, and the job's outcome waits for its index writes. Failed or partial indexing does not block writing: unchanged paper-backed occurrences remain available, and the result note lists papers whose past-exam years are missing. Derived exam texts, legacy sidecars, dot files and JSON state/index artifacts enter neither the preparation/upload plan nor automatic assessment classification. Automatic classification covers every original exam file, including `.xlsx` and `.xls` banks; a reused cached lecture manifest gains entries for originals it does not list. Automatic slide selection excludes general materials and files assigned to other lectures; cached general-material assignments are removed on reuse. Lectures without slides follow recorded order and need no slide figures. Neutral picture pages with no machine-readable description supply no required figure.

The terminal outcome is `finalized` with paths, summary and repair/omission notes, `failed` for exhausted recovery without publishable content, or `stopped` for disconnected internet, exhausted daily/account quota, expired sign-in or a missing recording. [pipeline_errors.py](scripts/pipeline_errors.py) distinguishes connection/DNS failures from retryable timeouts and per-minute limits. Gemini API daily quota renews at midnight Pacific; a provider-reported reset takes precedence and the client formats it in the student's local time. Account quota without a reported reset has an explicit unknown-renewal message. Interruption and explicit cancellation preserve parts for Continue. Duplicate jobs wait cancellably for the active lecture's actual terminal outcome, rather than reporting an unfinished job as complete.

The desktop [Remote](../packages/api/transcriber-engine/README.md#lecture-pipeline) defaults to six repair rounds, two-second initial backoff and a three-hour engine budget. It accepts finalized, failed and student-stop replies. Failed content recovery displays the original reason as a failed job without automatic transport-error retries. The tray marks a lecture done only after finalization; unexpected engine request failures retry retained-content recovery at most `pipelineRetryLimit` times (default 3), with exponential delays starting at `chatRepairCancelGraceMs` (default 30 seconds). The tray identifies the current retry step and attempt, then stops with a fixed note while retaining raw errors in details. The note is `Automatic retries stopped after repeated engine errors; your retained work is available through Continue.` Sessionless jobs restored after a reload resume with Continue. Conversation fallback applies when the Remote is unavailable; legacy conversation cancellation must release its writes before engine recovery. Standalone MCP callers receive the same terminal replies without a chat-repair step.

Long `write_parts_with_agy` calls emit MCP `notifications/progress` only when the request supplies `_meta.progressToken`. Each requested part reports its start and its successful staging; `progress` counts completed parts and `total` includes the questions part. Existing unrequested parts count as complete, while explicit replacements count as pending until staged. A failed write reports no completion checkpoint and retains the existing staged files.

The agy questions prompt places sourced patient scenarios in Clinical Cases, retains a sourced case when any sub-question is taught, prunes and renumbers only untaught sub-questions, and places IMP supplements after sourced cases. Complete-transcript and editorial validation reject recognizable sourced patient scenarios under Written Questions, sourced cases after IMP cases, and non-consecutive retained sub-question numbers. Semantic scope and missing sourced-case detection still require evidence review.

Guide writing starts with a `gemini-3.8-flash-low` organisation call over every recording's verbatim, labelled by recording and cohort. The staged `topics.json` stores unique spoken topics with English titles, Egyptian Arabic glosses, first/last word anchors, optional matched slide titles and exact/fuzzy/repaired anchor counts. Distinct spoken topics may reference the same slide. The parser ignores agy's `toolAction`/`toolSummary`, normalizes Arabic spelling and spacing, and accepts fuzzy token windows with at least 0.75 similarity and 60% matching tokens. Recording order constrains repeated anchors; deterministic boundary repairs preserve complete, non-overlapping coverage and topic ownership. Located starts order spans; overlapping tails clip at the next start, uniquely reversed anchors swap, and unusable tails use neighbour edges. Repairs count in `anchor_counts`. Missing recordings, ambiguous ownership, duplicate topics or more than one-third unplaceable anchors in a recording refuse the map. The cache fingerprint includes recording names, verbatim and the slide outline; unchanged inputs reuse the map, while changed inputs invalidate staged output. Cache version 3 reparses saved proposals before requesting a new map. Failed calls and unusable maps persist a recording-segment fallback, even when slides exist.

Consecutive topics form guide parts targeting 4,000 combined verbatim words, with at least two parts for lectures of 5,000 words or more when there are multiple topics. Every part receives all cohorts' topic slices, neighbouring context and the complete topic list with its assigned range marked. Each spoken topic has one `### English title — Egyptian Arabic gloss` heading; slides only help name topics and correct terms. Cohort labels appear only where explanations differ. Questions stay in the last part; topic parts use the existing merged-guide size floor, figure placement and saved-part recovery.

A discussed topic may contain one short `> **إضافة من الكتاب/السلايد — لم يشرحها الدكتور في التسجيل**` callout for an important skipped point. Other important unspoken items appear once at the guide's end in an optional `> [!summary]- في السلايدات ومتشرحش` folded callout, with every content line quoted. Selection uses ranked past-exam evidence and key numbers, classifications and definitions. The final guide prompt receives earlier guide text to exclude repeated additions. Validation names both duplicate topic headings and rejects malformed, repeated or misplaced folded summaries. Duplicate detection requires English-title and Arabic-gloss agreement after filtering generic and lecture-frequent vocabulary, with explicit section/subtopic and conflicting-number protection. Exact repeats are checked even without a gloss; related English-only titles remain separate. Numbered assessment and slide-case headings do not participate. Bilingual carrier/protein terms can supply complementary topic names across the title and gloss. The heading-only heuristic can miss semantic repeats; it does not prove identity or detect the overall slide-title-in-slide-order pattern. [Topic planning rationale](../.agents/notes/implemented/feature/2026-10-04-spoken-topics.md) explains the evidence and fallback choices.

## Source auto repair

Lecture phase 0 prepares selected authorities, references and required assessments. Unrelated unreadable files cannot block the lecture or enter its uploads. When local OCR fails on a PDF or JPG/JPEG/PNG/WebP/BMP image, Gemini through agy reads copied/rendered page images in a private temporary directory. PDF OCR also checks word confidence on the first three pages; recognized text below 60/100 confidence triggers model repair. Model repair has a 30-page cap and a shared five-minute rendering/model deadline; local PDF OCR and its confidence check share a five-minute budget. The prompt requires faithful text, page order and `[illegible]` markers, without summaries or other tools. Structural checks require usable text for every page; they cannot prove handwriting accuracy.

Content-hash caches preserve page-labelled Markdown, model provenance and a searchable PDF upload without editing originals. Repair failures are cached too; removing the matching `repair-failed.txt` permits a retry after fixing agy availability. Known unsupported formats use safe converters, including image-only office output that needs OCR. Selected manifest entries authorize their eligible prepared upload without a separate `approved_uploads` entry. An explicit lecture manifest proceeds through phase 0 independently of a module-wide source-sync checkpoint.

Unreadable supporting slides, notes and books are omitted with `[SOURCE-WARNING]` output in the MCP result. Library jobs persist warnings in their tray note, including nested tool results and completion followed by a provider error. Required recordings and classified exams/question banks remain blocking. Invalid manifests, ambiguous matches, unavailable required authorities and remote processing/upload errors remain failures. Explicit module-wide sync retains its approval requirement and partial status for unresolved sources because it has no selected lecture scope.

## Bounded review repair

Review uses only `Transcripts/Figures/<current lecture title>/figures.json` for slide requirements. An empty `figures` list requires no links; loose rasters and directories bearing old recording titles cannot demand images. Manual lecture decks resolve from definition `materials` by id or title. Review automatically extracts an absent, invalid or incomplete manifest, then reports missing manifest-listed files and links with guide-part placement candidates.

Slide manifests record the original deck's SHA-256 and byte size, selection options, per-page text/image observations and their SHA-256. Selected entries include image hashes and fingerprinted readings; preparation and review reject missing descriptions, modified images or inconsistent inputs. Selection version 6 refreshes earlier manifests. Consecutive textless single-picture slides remain eligible through the final page; only the deck's last isolated lone picture can be decorative, alongside named closings and empty pages without images.

For a selected picture-only slide, local tesseract `eng+ara` OCR supplies at least 20 characters with word confidence of at least 60. Sparse/low-confidence OCR falls back to an inspected agy vision caption in an image-only private directory; fences and completion metadata are stripped and long captions shortened. Page failures retain available OCR or a labelled neutral description with a per-page `reading.error`. Complete manifests accept these pages; explicit extraction retries failures and caches only successful readings by image SHA-256 and recognition policy. At most 30 vision calls share five minutes, with a 60-second deadline per page; exhausted aggregate budgets give remaining unread pages neutral labels. Machine readings in `figures.json`, `slides.txt` and writer `slide_text` are placement hints, never doctor's words. Initial extraction errors retry once; repeated failures produce the localized job note `Slide pictures could not be prepared; the transcript has none.`

A current extraction with present rasters restores figures hidden by a prior lecture-local omission. Writers receive the content figures and their OCR/vision readings; recognized title and closing pages are excluded from link requirements. Review first ranks OCR terms against every guide paragraph and its spoken topic, then requests bounded agy paragraph-index plans only for unresolved figures. Each request contains at most ten figures and 12 KB of paragraph text; at most twelve requests share three minutes. Placement inserts known links without rewriting narration or assessments and saves the updated staged parts. A valid described deck is not re-extracted for missing links. Review and final salvage list every content slide still unplaced in a folded `[!note]` callout at the guide's end, without claiming a paragraph match, instead of refusing the guide; final salvage first applies only local OCR matching. Only invalid image references are removed and reported.

Review, validation, provenance and finalize refusals instruct the agent to keep staged parts, replace affected numbers with `stage_draft_part` or `write_parts_with_agy(parts=[...])`, and retry `apply_review(from_parts=true)`. `read_draft(staged=true, part=N)` returns a retained part. Saved drafts without stages acquire 8 KB repair parts through `read_draft`; these preserve existing text and use the whole-guide substance checks rather than source-segment alignment. Replace these saved repair parts with `stage_draft_part`; agy refuses to remap them into source segments. Inline review rejects submitted or saved drafts over 20,000 UTF-8 bytes before extraction or validation. Never send the whole draft to repair a refusal. The [Agent Note](../.agents/notes/implemented/bug-fix/2026-10-04-bounded-review-repair.md) records the rationale.

## Retried topics and cancellable agy work

The topic organisation call gets ten minutes and one retry. Rejected answers persist as `rejected_proposal`, including raw malformed JSON; the retry receives the rejected answer and specific parser findings. A timeout, an unavailable agy or a network or quota failure is recorded in `topics.json` as a transient attempt and never reused: the next run asks again. Only a current-parser refusal with at least two attempts caches the recording-segment fallback. While it runs, the job's progress says the topics step can take minutes.

Clinical scenario lookup also accepts a unique paper question with substantial shared clinical wording and matching quantities, sex, laterality, negation and units. Corrections appear in review's `automatic_corrections` or validation's `[AUTO-REPAIR]` output and persist under `.transcriber-cache/review-repairs/`. Validation saves evidence corrections even when unrelated checks fail. The [self-repair note](../.agents/notes/implemented/bug-fix/2026-10-04-engine-self-repair.md) records lookup evidence limits; [deterministic lecture recovery](#deterministic-lecture-jobs) describes unresolved-provenance retention.

Long agy work (guide parts, topics, figure and source repair, web figures) runs under the MCP request's cancellation. A `notifications/cancelled` for the request, which the desktop sends when the student stops a job, kills the running `agy` process group and starts no further part; parts already staged stay for resume. The server keeps serving other requests.

## External illustrations

Guide writers may insert `<!-- qabas-web-figure {"description":"Keloid extending beyond the wound","search":"keloid scar","evidence":"literal excerpt from the recording"} -->` only for a doctor-described visual appearance absent from every extracted slide figure. The engine resolves at most five guide gaps per lecture before saving `apply_review`; unresolved, duplicate, ungrounded and non-guide placeholders disappear. Finalization also removes unresolved placeholders.

Pipeline guide prompts ask writers to identify helpful illustrations for appearances described in the doctor's words, such as mottled skin, distended neck veins, keloids and exophthalmos. A disease name alone cannot justify a request. Staged placeholders reach review resolution; `.web-figures.lock` is acquired only when a placeholder exists and web figures are enabled.

The engine uses the Wikimedia Commons File-namespace API with machine-readable metadata, a descriptive User-Agent, one request per second, eight-second HTTP deadlines and a 2 MiB download cap. It searches the writer's phrase, then its first four and first two content words and its last two (at most four queries), and downloads Commons' 1024 px thumbnail rather than a large original; SVG drawings arrive as PNG thumbnails. The external-illustration step has a shared ten-minute deadline and verifies at most four candidates per request. Only CC0, Public domain, CC BY and CC BY-SA are eligible: CC licenses need a matching Creative Commons deed URL (ported deeds included), Public domain and CC0 may have none; unknown, NC and ND licenses are rejected. A request's quote must come from the lecture: an exact substring, or every fragment of four or more words matching a lecture window at 0.75; the writer is told to copy 6-15 consecutive verbatim words exactly, ASR misspellings included. `web-figures-log.json` records each request's queries, verifier answers and outcome; see the [Agent Note](../.agents/notes/implemented/bug-fix/2026-10-05-web-figure-search.md). Openverse is not used.

Gemini through `agy` receives the downloaded image and the extracted slide images in a private temporary directory. It must inspect the candidate, confirm the appearance matches the literal lecture excerpt, and reject subjects already shown in a slide. Only strict JSON `answer: "yes"` with confidence at least 0.9 permits use. Unavailable agy, denied image reads, invalid JSON and any lookup, verification or persistence error produce no illustration. The installed agy binary contains `multimodal_view_file`; automated tests use fake HTTP and fake model responses, so live model accuracy is not established. There is no Gemini API-key fallback.

Approved originals live under `Transcripts/Figures/<lecture>/web/`; `web-figures.json` beside `figures.json` records source and file URLs, title, author, credit, license name and URL, description, literal evidence, verification and UTC retrieval time. Cached approvals require unchanged slide-image bytes. Recovery records use resolved part lengths; illustration requests and attribution blocks cannot satisfy narrated-content floors. The Arabic block labels each image **صورة توضيحية من برّه المحاضرة** and provides attribution. Validation requires the complete matching attribution block, accepted license, confident approval and an existing manifest-listed file. External images cannot satisfy the slide-image requirement. Final transcript trash and restoration carry the complete lecture figure directory, including external images and their manifest.

The workspace preference `.qabas-engine-settings.json` stores `web_figures`, enabled when absent. `get_engine_settings()` and `set_engine_settings(web_figures=false)` expose it through MCP. Desktop entries accept `--get-engine-settings` and `--set-web-figures on|off` with an explicit `--workspace`. The Host and Client API is documented in the [transcriber engine package](../packages/api/transcriber-engine/README.md). Disabled means no placeholder requests, Commons calls or image-verifier calls; already rendered illustrations remain valid. Corrupt preferences disable optional image requests, while settings read/set operations report the error.

The [Agent Note](../.agents/notes/implemented/feature/2026-10-04-web-figures.md) records the conservative approval policy and its limitations.

Exam management prepares one original at a time with `prepare_exam_file(module, path)`. PDFs, Office documents and images retain their original bytes; existing conversion and OCR produce searchable text before `build_exam_index`. XLSX values and DOCX paragraphs or tables are passed to agy with their original locations. Original SHA-256, generated text ownership and per-file preparation failures live in `.transcriber-cache/exam-texts.json`; generated text uses the full original name plus `.txt` and is hidden from original-file inventories. Replacement, rename and trash invalidate the owned text and index. Inventories distinguish prepared text from a current agy index and report per-file question and review counts. An invalid or old index remains stale while original-file management stays available. Successful preparation and validated model batches survive failures in other papers; retry reuses only unchanged originals. OCR can call agy when local recognition fails.

The frozen build downloads the pinned, SHA-256-verified `eng`, `ara`, and `osd` Tesseract models from [tessdata_fast](https://github.com/tesseract-ocr/tessdata_fast) into `.build/tessdata` and packages them with the pinned `pdf`, `txt`, `tsv`, and `hocr` renderer configs from Tesseract. The configs enable OCRmyPDF output and word-confidence reports when the bundled directory overrides system data. An incomplete bundled directory fails before tool execution. All assets use Apache-2.0; see [the manifest](tessdata.manifest.json) and [license](TESSDATA-LICENSE). Windows discovery includes Scoop shims and the portable LibreOffice program directory. Run `python engine/prepare_ocr_data.py` from the repository root to prepare the same models for source runs.

Lecture uploads require FFmpeg. Qabas compresses each missing or failed local recording into a private mono AAC copy before uploading, retains the original bytes, and reuses only copies whose original and prepared SHA-256 match. Encoder output larger than the original does not replace the smaller upload. Set `TRANSCRIBER_CONFIG_PATH` to an absolute persistent JSON file before launching Qabas to configure both installed and source engines; the child engine inherits this setting. Missing, unreadable or invalid explicit files stop the operation. Source runs without that override use `engine/scripts/config.json`. The JSON object accepts `recording_upload_bitrate_kbps` (16–128, default 48), `recording_upload_sample_rate` (16000, 22050, 24000, 32000, 44100 or 48000; default 24000), and `recording_compression_timeout_seconds` (1–3600, default 600). Compression publishes complete output atomically and removes staged output on cancellation. The app shows compression, upload and NotebookLM processing separately. A failed remote recording is reuploaded automatically; only failed sources with the exact original name are removed, after a replacement becomes ready. Ready and processing sources are reused without duplicate uploads.

Transcription selection carries the full recording filename so a local or NotebookLM recording can be matched exactly when audio formats share a stem. Recording and slide requests resolve to a full-name match before any stem match, so `L2.pdf` names the PDF even beside `L2.mp3`. Extensionless titles still use stem matching, and a remaining stem-only ambiguity names every candidate file. Transcript and draft names omit only a trailing supported recording extension, ignoring case; other dots remain part of the lecture title.

Exam reading is automatic. PDF inspection rejects format-control characters above `ocr_format_control_limit` (default 0.02), or fragmented tokens and isolated Arabic words above `ocr_script_noise_limit` (default 0.60). Source-manifest entries accept both limits as numbers strictly between zero and one. Exam preparation reads the same keys and `ocr_language` (default `eng+ara`) from the engine JSON configuration. Clean searchable papers retain their text layers. Each unsuccessful preparation request retries local recognition once, adding supported rotation and deskew flags discovered through `ocrmypdf --help`; cached failure text never prevents a later request. Missing executables or language data return `status: failed`, `code: ocr_tool_missing`, and installer identifiers in `tools` (`ocrmypdf`, `tesseract`, or `ghostscript`). Linux and macOS Tesseract installation routes include multilingual data so an Arabic-data failure can recover through the existing installer.

A same-stem `.txt` beside a supported document directly in `Questions/` is a legacy sidecar, matched without case sensitivity. The preparation state retains its filename in optional `sidecar`; inventories and indexing count only the document. Pairing-only records have `prepared: false` and do not claim ownership of generated text. Successful preparation replaces that record with owned derived text; optional `fallback: true` means the unchanged legacy text supplied the derived copy after document reading failed. Later explicit requests retry document reading rather than reusing fallback text. Older records without these fields remain valid. Student sidecars are never renamed or deleted.

Engine file locks wait until acquired on Windows and POSIX, with request cancellation checked between attempts. `lock_file` and `exclusive_file_lock` accept an optional timeout in seconds; timeout and non-blocking contention raise `ModuleBusy`, which remains an `AlreadyLocked` and `BlockingIOError`. Holder diagnostics use `module`, `operation`, and `pid` JSON fields after the reserved byte 0; lecture locks also retain `lecture_key` and `title`. Busy launcher errors name the module and operation and ask the caller to wait; other OS errors retain their original diagnostics. Exam preparation holds a per-paper lock and module activity lease through extraction, releases the lecture-registry lock during extraction, and publishes only when source bytes and that paper's preparation record still match. Cancellation releases activity leases even when the request can no longer acquire the admission gate. Windows CI runs Python 3.12 lock, preparation, and module activity regressions with `TRANSCRIBER_AGY=off`; Ubuntu retains the full engine checks.

Desktop exam inventory checks each published source against its original SHA-256 independently. Matching sources set `indexed` and question/review counts; matching published failures set `index_failed`, `index_error` and, for failures recorded with one, `index_failure_cause`: `source` when the file could not be read, `model` when the agy run did not complete, and `auth` when agy reported a missing or expired sign-in. `question_index_counts` reports indexed, failed and pending originals. Module status is `built` when all originals match, `partial` when only some match, `stale` when an index exists but none match, and `missing` without an index. An older extractor reports `legacy`; its questions remain readable, and sources without recorded SHA use `index_legacy` rather than claiming an indexed match.
