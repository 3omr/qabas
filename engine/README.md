# Qabas transcription engine

This directory contains Qabas's Python engine, copied from the universal-transcriber skill repository at commit `c1168da`. Qabas owns this copy and its tests independently. Runtime and tests require no skill checkout, skill instructions, mirror, installer, or skill release metadata. The app reports its own version and does not check for skill updates.

The scripts require Python 3.10 or later. Create the environment from this repository root:

```sh
python3 -m venv engine/.venv
engine/.venv/bin/python -m pip install -r engine/requirements.txt -r engine/requirements-dev.txt
pnpm run engine:test
pnpm run engine:lint
pnpm run engine:typecheck
```

On Windows, use `engine/.venv/Scripts/python.exe`. The root commands select that environment when present, otherwise `python3`. `engine:test` runs unittest discovery; the additional desktop cases use pytest (`engine/.venv/bin/python -m pytest engine/tests`). CI runs both suites and the two static checks. NotebookLM, OCR, office conversion and media commands remain external dependencies; run `engine/.venv/bin/python engine/scripts/run_transcription.py --doctor` to inspect them. The optional Whisper backend needs the packages listed in [requirements.txt](requirements.txt).

Run the MCP server or apply the app's patch:

```sh
engine/.venv/bin/python engine/scripts/mcp_server.py --help
pnpm dsh --profile web --patch engine/transcriber.cordis.yml
```

Activate the environment before using the source profile so `python3` finds its dependencies. `TRANSCRIBER_ENGINE_ROOT` overrides this directory; `TRANSCRIBER_SKILL_ROOT` remains a legacy override. Student data defaults to the operating-system home plus `Qabas Library`, created with `modules/` on first use. `TRANSCRIBER_WORKSPACE` is a developer and test override. Saved workspace pointers and cwd do not select the library. Explicit `--workspace` remains available for developer CLI calls. [Host resolution](../packages/api/transcriber-engine/README.md) defines workspace selection and errors.

For the desktop sidecar, install [requirements-build.txt](requirements-build.txt), then run `pnpm run engine:build` (or `bash engine/build-engine.sh` from any directory). Build on the target OS and architecture. The script produces `engine/dist/transcriber-engine-<target-triple>[.exe]`; `TRANSCRIBER_DIST_DIR` and `TRANSCRIBER_PYINSTALLER_WORKDIR` override output directories. Desktop preparation copies the native sidecar and [MCP patch](transcriber.cordis.yml) into `runtime/app/engine/`, which Tauri includes through its existing runtime resource mapping. The binary contains the app version and runtime references. The build script verifies its help entry, MCP initialization version and packaged editorial reference before reporting success.

The runtime [editorial guide](references/drafting-and-editorial.md) and [grouping cases](references/lecture-grouping-cases.json) are the only copied skill references. Python and TypeScript tests read the same grouping JSON. Omitted test files are `test_anki_extraction.py` and `test_anki_generator.py` (the separate Anki skill), `test_next_version.py` (skill release machinery), and `test_version_checker.py` (skill updates and shared skill-version metadata). Their 75 unittest cases account for the difference from the source's 716 cases. The launcher-discovery tests instead pin the bundled sibling script and reject a missing bundled engine; student workspaces are never searched for engine code.

Lecture visibility is module-owned metadata. `module.json` stores safe recording names relative to `Lecture/` in `hidden_recordings`; `hidden_transcripts` retains the recording association for existing transcripts with legacy custom titles. `hide_lecture(module, title)` hides a defined or automatic unit and removes its manual definition atomically under the registry lock. A manual id disambiguates duplicate titles. `restore_recordings(module, recordings)` removes selected names from the hidden list without recreating definitions. Neither operation changes source files, NotebookLM sources or transcript files. Hidden recordings remain in file inventory with `hidden: true`, are excluded from unassigned organization sources, and cannot be used in a definition until restored. Fully hidden units and their orphan transcript rows are omitted from library listings; partially restored units contain only visible recording sources.

The MCP tools run without a chat through the Host registry Remotes. Direct source and packaged entry points also accept `run_transcription.py --workspace <workspace> --module <module> --hide-lecture <title>` or `--restore-recordings <name>...`; the sidecar uses its `run-transcription` subcommand with the same flags.

Reversible removal uses `remove_transcript(module, title, kinds)` with a non-empty subset of `final`, `draft`, and `verbatim`, plus `list_trash(module)` and `restore_trash(module, id)`. Selected outputs share one `.transcriber-cache/trash/<UTC timestamp>/` entry. Final removal includes figures, matching Anki outputs and the linked Index row; recordings, slides, definitions and NotebookLM remain untouched. Index edits are atomic and preserve remaining bytes. Matching run checkpoint directories move with the outputs and matching batch-ledger records are cleared so a new job cannot resume removed phases. Draft removal also archives its staged parts and validation metadata to prevent reuse of the removed text. Restoration puts them back, preserving unrelated later Index and batch changes. Destination conflicts refuse before any file moves.

`remove_module(module)` renames the entire module to `<workspace>/.qabas-trash/modules/<id>--<UTC timestamp>/`; `list_removed_modules()` lists archives and `restore_module(trash_id)` refuses a reused id. Results explicitly report `notebook_untouched: true`. Engine-held activity leases protect launcher and MCP operations, and removals refuse held module, lecture, batch or Index locks. Browser job records are client-local, so the guard cannot identify an idle chat between engine calls. Trash is never automatically purged. Legacy file trash and hidden recordings remain restorable; older hidden metadata uses its modification time when no original removal time was recorded. Lecture restoration unhides recordings without recreating manual definitions; new hide entries retain the original module metadata for history.

The same tools run through desktop Remotes without a chat. Direct CLI entries use `--remove-transcript <title> --transcript-kinds final draft`, `--list-trash`, `--restore-trash <id>`, `--remove-module <id>`, `--list-removed-modules`, and `--restore-module <trash-id>`. The sidecar's `run-transcription` subcommand uses those flags.

### Deterministic lecture jobs

`run_lecture_pipeline(module, lecture, mode, confirmed=true)` completes `transcribe`, `redo`, or `continue` without a chat model. The lecture button authorizes uploading its recordings, saving review and finalizing. The runner in [lecture_pipeline.py](scripts/lecture_pipeline.py) composes existing tool handlers: `begin_lecture` resolves the unit, uploads missing recordings, prepares the source manifest and exam index, extracts figures and fetches missing verbatims; `write_parts_with_agy` prepares the cached topic map, reads lecture evidence and questions, and writes missing parts; `apply_review(from_parts=true)` saves the draft; `validate_draft` and `verify_provenance` check it; `finalize` commits the transcript and updates `Index.md`. Existing heading cleanup, figure extraction recovery, question deduplication and renumbering remain owned by those tools. The pipeline does not run a module-wide source sync or upload unrelated files.

MCP progress reports each preparation step, writing part and repair when `_meta.progressToken` is supplied. Request cancellation and the effort deadline stop owned subprocess trees and backoff waits; completed parts remain available. Continue reuses staged parts and saved drafts, including an interrupted redo beside its existing final transcript. Redo preserves the existing final transcript until successful finalization. Changed saved bytes always require fresh validation and provenance checks.

Recovery in [pipeline_repair.py](scripts/pipeline_repair.py) escalates from existing deterministic cleanup to rewrites of affected parts, then smaller source slices staged in the same part layout. Transient 5xx, overload, timeout, truncated-output and per-minute 429 errors retry with cancellable exponential backoff. Failed inputs are refreshed, figures are re-extracted or omitted with a lecture-local manifest note, and unusable topic layouts retain recording-based repair text. A last-resort `handoff` carries only the specific findings and retained manifest to chat; the client then requests `salvage` if chat does not finalize. Salvage archives original stages, removes unverifiable questions and optional supporting content, and validates the retained transcript before finalization. If the explanation cannot be validated, the complete doctor verbatim replaces it with an explicit note. Mandatory validation and provenance checks remain enabled.

The terminal outcome is `finalized` with paths, summary and repair/omission notes, or `stopped` for disconnected internet, exhausted daily/account quota, expired sign-in or a missing recording. [pipeline_errors.py](scripts/pipeline_errors.py) distinguishes connection/DNS failures from retryable timeouts and per-minute limits. Gemini API daily quota renews at midnight Pacific; a provider-reported reset takes precedence and the client formats it in the student's local time. Account quota without a reported reset has an explicit unknown-renewal message. Both interruptions and cancellation preserve retained parts for Continue. Internal `handoff` and `completed` outcomes never become failed/needs-attention tray states. `completed` does not claim finalization: if unavailable engine storage or mandatory source evidence prevents any valid commit, its note says that retained work is available for Continue.

The desktop [Remote](../packages/api/transcriber-engine/README.md#lecture-pipeline) defaults to six recovery rounds, two-second initial backoff and a three-hour total engine budget. The client bounds chat repair to five minutes and reserves time for validated salvage; cancellation of chat must release its writes before salvage starts. Defaults are deployment-configurable. A standalone MCP caller handles `handoff` by repairing the specified parts and returning with `salvage=true`; it must not send the complete draft to a model.

Long `write_parts_with_agy` calls emit MCP `notifications/progress` only when the request supplies `_meta.progressToken`. Each requested part reports its start and its successful staging; `progress` counts completed parts and `total` includes the questions part. Existing unrequested parts count as complete, while explicit replacements count as pending until staged. A failed write reports no completion checkpoint and retains the existing staged files.

The agy questions prompt places sourced patient scenarios in Clinical Cases, retains a sourced case when any sub-question is taught, prunes and renumbers only untaught sub-questions, and places IMP supplements after sourced cases. Complete-transcript and editorial validation reject recognizable sourced patient scenarios under Written Questions, sourced cases after IMP cases, and non-consecutive retained sub-question numbers. Semantic scope and missing sourced-case detection still require evidence review.

Guide writing starts with a `gemini-3.8-flash-low` organisation call over every recording's verbatim, labelled by recording and cohort. The staged `topics.json` stores unique spoken topics with English titles, Egyptian Arabic glosses, first/last word anchors, optional matched slide titles and exact/fuzzy/repaired anchor counts. Distinct spoken topics may reference the same slide. The parser ignores agy's `toolAction`/`toolSummary`, normalizes Arabic spelling and spacing, and accepts fuzzy token windows with at least 0.75 similarity and 60% matching tokens. Recording order constrains repeated anchors; deterministic boundary repairs preserve complete, non-overlapping coverage and topic ownership. Located starts order spans; overlapping tails clip at the next start, uniquely reversed anchors swap, and unusable tails use neighbour edges. Repairs count in `anchor_counts`. Missing recordings, ambiguous ownership, duplicate topics or more than one-third unplaceable anchors in a recording refuse the map. The cache fingerprint includes recording names, verbatim and the slide outline; unchanged inputs reuse the map, while changed inputs invalidate staged output. Cache version 3 reparses saved proposals before requesting a new map. Failed calls and unusable maps persist a recording-segment fallback, even when slides exist.

Consecutive topics form guide parts targeting 4,000 combined verbatim words, with at least two parts for lectures of 5,000 words or more when there are multiple topics. Every part receives all cohorts' topic slices, neighbouring context and the complete topic list with its assigned range marked. Each spoken topic has one `### English title — Egyptian Arabic gloss` heading; slides only help name topics and correct terms. Cohort labels appear only where explanations differ. Questions stay in the last part; topic parts use the existing merged-guide size floor, figure placement and saved-part recovery.

A discussed topic may contain one short `> **إضافة من الكتاب/السلايد — لم يشرحها الدكتور في التسجيل**` callout for an important skipped point. Other important unspoken items appear once at the guide's end in an optional `> [!summary]- في السلايدات ومتشرحش` folded callout, with every content line quoted. Selection uses ranked past-exam evidence and key numbers, classifications and definitions. The final guide prompt receives earlier guide text to exclude repeated additions. Validation names both duplicate topic headings and rejects malformed, repeated or misplaced folded summaries. Duplicate detection requires English-title and Arabic-gloss agreement after filtering generic and lecture-frequent vocabulary, with explicit section/subtopic and conflicting-number protection. Exact repeats are checked even without a gloss; related English-only titles remain separate. Numbered assessment and slide-case headings do not participate. Bilingual carrier/protein terms can supply complementary topic names across the title and gloss. The heading-only heuristic can miss semantic repeats; it does not prove identity or detect the overall slide-title-in-slide-order pattern. [Topic planning rationale](../.agents/notes/implemented/feature/2026-10-04-spoken-topics.md) explains the evidence and fallback choices.

<a id="source-auto-repair"></a>

## Source auto repair

Lecture phase 0 prepares selected authorities, references and required assessments. Unrelated unreadable files cannot block the lecture or enter its uploads. When local OCR fails on a PDF or JPG/JPEG/PNG/WebP/BMP image, Gemini through agy reads copied/rendered page images in a private temporary directory. PDF OCR also checks word confidence on the first three pages; recognized text below 60/100 confidence triggers model repair. Model repair has a 30-page cap and a shared five-minute rendering/model deadline; local PDF OCR and its confidence check share a five-minute budget. The prompt requires faithful text, page order and `[illegible]` markers, without summaries or other tools. Structural checks require usable text for every page; they cannot prove handwriting accuracy.

Content-hash caches preserve page-labelled Markdown, model provenance and a searchable PDF upload without editing originals. Repair failures are cached too; removing the matching `repair-failed.txt` permits a retry after fixing agy availability. Known unsupported formats use safe converters, including image-only office output that needs OCR. Selected manifest entries authorize their eligible prepared upload without a separate `approved_uploads` entry. An explicit lecture manifest proceeds through phase 0 independently of a module-wide source-sync checkpoint.

Unreadable supporting slides, notes and books are omitted with `[SOURCE-WARNING]` output in the MCP result. Library jobs persist warnings in their tray note, including nested tool results and completion followed by a provider error. Required recordings and classified exams/question banks remain blocking. Invalid manifests, ambiguous matches, unavailable required authorities and remote processing/upload errors remain failures. Explicit module-wide sync retains its approval requirement and partial status for unresolved sources because it has no selected lecture scope.

## Bounded review repair

Review uses only `Transcripts/Figures/<current lecture title>/figures.json` for slide requirements. An empty `figures` list requires no links; loose rasters and directories bearing old recording titles cannot demand images. Manual lecture decks resolve from definition `materials` by id or title. Review automatically extracts an absent, invalid or incomplete manifest, then reports missing manifest-listed files and links with guide-part placement candidates.

Review, validation, provenance and finalize refusals instruct the agent to keep staged parts, replace affected numbers with `stage_draft_part` or `write_parts_with_agy(parts=[...])`, and retry `apply_review(from_parts=true)`. `read_draft(staged=true, part=N)` returns a retained part. Saved drafts without stages acquire 8 KB repair parts through `read_draft`; these preserve existing text and use the whole-guide substance checks rather than source-segment alignment. Replace these saved repair parts with `stage_draft_part`; agy refuses to remap them into source segments. Inline review rejects submitted or saved drafts over 20,000 UTF-8 bytes before extraction or validation. Never send the whole draft to repair a refusal. The [Agent Note](../.agents/notes/implemented/bug-fix/2026-10-04-bounded-review-repair.md) records the rationale.

## Retried topics and cancellable agy work

The topic organisation call gets ten minutes and one retry. Rejected answers persist as `rejected_proposal`, including raw malformed JSON; the retry receives the rejected answer and specific parser findings. A timeout, an unavailable agy or a network or quota failure is recorded in `topics.json` as a transient attempt and never reused: the next run asks again. Only a current-parser refusal with at least two attempts caches the recording-segment fallback. While it runs, the job's progress says the topics step can take minutes.

Review, `validate_draft` and `verify_provenance` correct conclusive badge mismatches without a model call. Question-bank evidence produces `**[Question Bank]**`; dated question evidence produces `**[Past Exams - <evidenced years>]**`, with years parsed through `exam_years.py`. Clinical scenario lookup also accepts a unique paper question with substantial shared clinical wording and matching quantities, sex, laterality, negation and units. Unknown sources and uncertain matches remain findings for bounded part repair. Corrections preserve source lines and question prose, appear in review's `automatic_corrections` or validation's `[AUTO-REPAIR]` output, and persist under `.transcriber-cache/review-repairs/`. Validation saves confirmed corrections even when unrelated checks fail. The [self-repair note pair](../engine-self-repair-notes.patch) records the evidence limits.

Long agy work (guide parts, topics, figure and source repair, web figures) runs under the MCP request's cancellation. A `notifications/cancelled` for the request, which the desktop sends when the student stops a job, kills the running `agy` process group and starts no further part; parts already staged stay for resume. The server keeps serving other requests.

## External illustrations

Guide writers may insert `<!-- qabas-web-figure {"description":"Keloid extending beyond the wound","search":"keloid scar","evidence":"literal doctor or slide excerpt"} -->` only for a described visual appearance absent from every extracted slide figure. The engine resolves at most five guide gaps per lecture before saving `apply_review`; unresolved, duplicate, ungrounded and non-guide placeholders disappear. Finalization also removes unresolved placeholders.

The engine uses the Wikimedia Commons File-namespace API with machine-readable metadata, a descriptive User-Agent, one request per second, eight-second HTTP deadlines and a 2 MiB download cap. The external-illustration step has a shared two-minute deadline. Only CC0, Public domain, CC BY and CC BY-SA with a matching Creative Commons URL are eligible; unknown, NC and ND licenses are rejected. Files must be raster images; oversized originals are skipped without resizing or an added Pillow dependency. Openverse is not used.

Gemini through `agy` receives the downloaded image and the extracted slide images in a private temporary directory. It must inspect the candidate, confirm the appearance matches the literal lecture excerpt, and reject subjects already shown in a slide. Only strict JSON `answer: "yes"` with confidence at least 0.9 permits use. Unavailable agy, denied image reads, invalid JSON and any lookup, verification or persistence error produce no illustration. The installed agy binary contains `multimodal_view_file`; automated tests use fake HTTP and fake model responses, so live model accuracy is not established. There is no Gemini API-key fallback.

Approved originals live under `Transcripts/Figures/<lecture>/web/`; `web-figures.json` beside `figures.json` records source and file URLs, title, author, credit, license name and URL, description, literal evidence, verification and UTC retrieval time. Cached approvals require unchanged slide-image bytes. Recovery records use resolved part lengths; illustration requests and attribution blocks cannot satisfy narrated-content floors. The Arabic block labels each image **صورة توضيحية من برّه المحاضرة** and provides attribution. Validation requires the complete matching attribution block, accepted license, confident approval and an existing manifest-listed file. External images cannot satisfy the slide-image requirement. Final transcript trash and restoration carry the complete lecture figure directory, including external images and their manifest.

The workspace preference `.qabas-engine-settings.json` stores `web_figures`, enabled when absent. `get_engine_settings()` and `set_engine_settings(web_figures=false)` expose it through MCP. Desktop entries accept `--get-engine-settings` and `--set-web-figures on|off` with an explicit `--workspace`. The Host and Client API is documented in the [transcriber engine package](../packages/api/transcriber-engine/README.md). Disabled means no placeholder requests, Commons calls or image-verifier calls; already rendered illustrations remain valid. Corrupt preferences disable optional image requests, while settings read/set operations report the error.

The [Agent Note](../.agents/notes/implemented/feature/2026-10-04-web-figures.md) records the conservative approval policy and its limitations.
