# Agent Note: 后台资料库任务观察共享的 Session 呈现

Status: implemented

[English](2026-10-01-library-background-jobs.md) | 中文

## 问题

资料库优先界面让学习资料可直接读取，但把每个操作发送到可见对话又使聊天成为工作界面。学生需要在资料库中排队转写、查看进度和回答问题，同时保留打开底层对话的能力。

## 决策

LibraryJobs 负责稳定任务身份，以及受已验证并发设置约束的 FIFO 启动。每个任务拥有一个 transcriber 会话；运行器观察公共 Session 生命周期快照、Conversation 的 Chat 目标和 ui-session 的有效待处理交互映射。它调用待答问题对象自身的回答方法，让资料库和输入框的回答结算同一个请求。本地持久化保留任务身份和结果，不保留可回答的问题对象。

Session Controller 的公共 `sessions.watch(id)` 返回 `SessionWatch`，包含打开时的 `ready` Promise 和幂等的异步 `release()`。观察共享面板导航打开的同一个 Session 事件源。最后一次仅供后台使用的保留释放会关闭 Remote 迭代器，并保留可读事件窗口；新的观察会打开全新快照。通过面板导航打开的会话在所有后台观察释放后仍保持原有事件源生命周期。作用域移除与 controller 销毁都会关闭保留的事件源，迟到的释放不会关闭具有相同身份的替代作用域。

运行器在等待就绪或发送 prompt 前，通过 Cordis effect 注册每个观察及其可观察订阅。完成会释放保留，关闭任务记录会移除已经释放的终态记录，插件销毁会等待尚未完成的事件流清理。释放客户端事件源不会中断 Host Agent。转写成功要求最后一次 transcriber 调用是成功的 finalize；模块任务要求记录中的回合正常结束。等待问题占用并发名额，并可从任一呈现入口回答。

## 考虑过的替代方案

**选中会话后恢复原选择。** 否决，因为打开后台任务会改变可见导航，并使进度依赖面板选择的生命周期。

**在资料库内实现第二套事件流投影。** 否决，因为历史分页、流恢复、紧凑助手记录和对话组装已有各自的负责者；重复实现会使进度和摘要不一致。

**只在打开完成后返回释放回调。** 否决，因为插件在首次历史请求期间销毁时，必须在该请求完成之前释放事件源。句柄立即提供清理方法，并单独提供就绪状态。

## 后果

后台任务在任何对话打开之前就能收到进度和回合结束观察。重新加载会重新连接活动会话，不再次发送其 prompt。任务记录与并发控制仅在浏览器客户端本地生效，不协调多个标签页。正常对话导航与 Host Agent 生命周期保持原有行为。

## 验证

Controller 测试覆盖共享保留、幂等释放、面板接管、打开期间释放、业务与组装错误、移除、替代作用域及根上下文销毁。运行器回归测试使用真实的 ClientSessions、UiConversation 和 Chat 定义，并通过 Session Controller 的可编程 Remote 测试替身驱动：从未被选中的会话发布草稿进度、共享问题、完成任务、释放历史，并启动排队工作。全新 controller 通过保存的历史重新连接持久化任务，不选中其会话，也不再次发送 prompt。首次打开期间销毁会释放事件源，而不提交 prompt。夹具观察测试验证公共测试替身遵循同样的保留与选择规则。
