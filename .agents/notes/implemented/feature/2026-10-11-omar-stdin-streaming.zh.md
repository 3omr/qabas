# Agent Note: Omar 的紧凑 stdin 传输与临时流式输出

Status: implemented

[English](2026-10-11-omar-stdin-streaming.md) | 中文

## 问题

学生聊天提供方在 Qabas 的每个模型步骤中启动一次已登录的 Antigravity CLI。报告的 agy 1.3.3 测量值（gemini-3.8-flash-low，低推理强度）为：普通问题 10 秒 / 35.2K 输入 token；需要两次资料库调用的问题在两个步骤中共 164 秒 / 100K 输入 token，缓存命中率为 0%。

## 决定

每个步骤使用一个新进程，参数为 `--input-format stream-json --output-format stream-json`。stdin 上的单条 `event:user` 消息承载已记录请求的确定性紧凑渲染。关闭 stdin 后 CLI 在该轮结束。空的私有工作目录中没有提示词文件；响应模式位于其外。`--disable-slash-commands` 防止提示词展开。工具定义保留每个 JSON Schema 字段，每个工具的描述只出现一次。没有隐藏的续接状态、模式缓存、时间戳或会话 id 影响后续请求。

NDJSON 解码器只把模式答案的 `text` 字段通过现有的 LLM 流发布，该流已经通过 Assistant 流事件到达聊天界面。CLI 的说明文字、围栏或嵌套的 JSON 以及工具参数 JSON 都不会发布。终结结果在发布可执行调用之前会验证每个工具名称和 JSON 对象参数。与结果不一致的流式前缀会导致失败。临时文本之后的错误会通过现有的循环结算产生一次失败的 Assistant 尝试；它们永远不会发布工具块。CLI 内部工具事件会让请求失败，但 agy 自己用来结束每个模式答案的 `finish` 工具除外。解码器分别解析每个 agent_response 轮次，因为 agy 会在第二轮中复述答案。这能检测工具使用，但不能替代 Antigravity 自身的权限控制。

共享的子进程所有者保留取消、超时、进程树终止和退出观察。生成器关闭时也会取消其操作并等待清理完成。完整的 NDJSON 字节数（包括元数据）受现有经过验证的 `maxOutputBytes` 限制；`timeoutMs`、`graceMs`、可执行文件、模型、推理强度和回退字段仍归配置所有。提供方中没有新增硬编码的可调参数。增量字符串转义处理由一个有维护的 partial-JSON 解析器提供，而不是自行编写 JSON 解析器。

## 测量

测量语料是已提交的 `omar-google-fallback` 会话中的第一个已记录请求，并展开了其自有的系统提示词和工具模式附属文件。不包括学生的私有资料库数据。缩进的基线为 71,560 UTF-8 字节；紧凑渲染为 53,657 字节：减少 17,903 字节 / 25.018%。录制输入快照固定了紧凑字节数和 SHA-256，并比较全部会话内容和完整的工具定义。这些字节数不是 token 数。

在编排者机器上（agy 1.3.3，gemini-3.8-flash-low，低推理强度）用可选脚本对一句话请求进行的主机测量：prompt.md 路径在 4.9 秒后到达 init，9.4 秒后出现首段答案文本，16.3 秒后退出，其中包含一个 view_file 步骤；stdin 路径在 3.6 秒后到达 init，6.5 秒后出现首段答案文本，11.4 秒后退出，没有文件步骤。在产品聊天中，一个需要一次资料库工具调用的问题在 27 秒内完成，使用 51.2K token；而此改动之前，可比较的两步轮次需要 164 秒和 100K token。

诊断脚本报告带时间戳的 init 和步骤事件、分别报告原始首段文本和解码后的首段答案、每个步骤的工具/模型耗时及首尾事件时间、终结的用量、解析/解码时间以及进程总时间。工具耗时只衡量工具执行；之前的模型等待需要从事件时间线中读取。CLI 从启动到 init 的时间包含 CLI 的认证/准备，无法拆分内部服务器阶段。对每个已记录的 Qabas 步骤分别运行，再相加得到一个普通轮次的时间。此诊断不测量浏览器实际绘制时间。

## 考虑过的替代方案

**用 prompt.md 输出流式结果。** 作为诊断的 file 模式保留。它可以更早地显示文本，但仍要求读取文件，并可能多一次模型往返。上述主机运行测得多了一个 view_file 步骤，退出时间多约 5 秒。

**小的 argv 提示词。** 作为诊断的 argv 模式保留，用于小提示词的对照。完整的已记录请求会超过 Windows 的命令行限制，最终也会超过 Linux 的单参数限制，因此 argv 无法承载一般的聊天请求。

**`--conversation <id>` 或常驻的 stdin 进程。** 未采用。[官方 CLI 文档](https://www.antigravity.google/docs/cli/headless/)展示了复用和累计计数，但保存的 id 本身并不会把 CLI 私有的先前轨迹、工具结果、检查点文本或注入的上下文序列化到 Qabas 会话中。只记录发送的用户消息无法重建这些模型可见的历史。支持续接需要持久的轨迹所有权和重放依据，以及针对该状态的取消和恢复规则。脚本只在明确的主机对比中接受该参数并报告得到的 id；提供方从不发送它。

**发布原始 text_delta。** 被否决，因为模式模式下的增量可能包含原始响应 JSON 或 CLI 说明文字；这些都不是给学生的答案文本。提前进行的模式文本解码在最终验证之前都是临时的。

## 被取代的记录

本记录部分取代 `.agents/notes/implemented/feature/2026-10-10-omar-chat-model.md` 中关于传输和缓冲的段落。其中的配置、Google 回退、明确固定的模型以及工具执行的所有权仍然有效。

## 后果

stdin 从设计上消除了 argv 的大小限制和额外的文件读取请求。流式输出让解码后的答案文本在假 CLI 握手中于进程退出之前可用，上述主机测量也显示了时间的减少。完整的历史和工具描述仍会在每个新步骤中发送一次；不声称存在跨步骤的 token 缓存。现有的 Gemini 回退钩子保留。没有引入客户端运行时导入，也没有修改循环。

## 验证

假 CLI 测试覆盖紧凑渲染、通过 stdin 传输的超过 256 KiB 的提示词、退出前的文本、录制的 agy 事件顺序（包括 finish 工具）、文本之后的取消以及父进程和子进程的退出、格式错误/缺失/重复的结果、多字节的字节限制、认证和配额故障、未知调用、不一致的流式前缀以及 Google 回退。无需密钥的 `omar-google-fallback` 快照通过 headless 配置文件重放。`QABAS_AGY_LIVE=1 node --import tsx/esm packages/llm/llm-agy/tests/live.mjs stdin <request.json>` 可重复主机测量；没有该变量时脚本直接退出，不会启动 agy。
