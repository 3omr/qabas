# Agent Note：首次设置是一条统一风格的流程

Status: implemented

[English](2026-10-01-first-run-setup.md) | 中文

## 问题

新学生会在被模糊的应用之上连续遇到两个弹窗：先是测试声明，然后是一个提供方选择器，按配置 id（`openai-codex`、`xiaomi-token-plan-sgp`）列出 39 个提供方，还谈到 API 密钥。应用所需的其他东西——转写工具、NotebookLM、学习工作区——都不在开始流程之中。

## 决定

每个首次设置步骤都绘制在同一个全屏框架里，即 [ui-primitives](../../../../packages/client/ui-primitives/README.zh.md) 中的 `SetupStage`：纸张色调配余烬光晕、进度条，并把焦点放在步骤标题上。每个步骤从 `settings.onboarding` 登记表（按 order 排序）读取自己的位置，因此来自四个包的步骤彼此无需了解，也能组成一个连贯的序列：

1. 欢迎——测试声明重绘为欢迎页（其确认逻辑不变），产品标志通过品牌插件填充的 `settings.onboarding.mark` 插槽显示。
2. AI 账户——ChatGPT、Claude 和 Gemini 以三张大卡片呈现，完整目录放在"更多选项"之后，并用产品名称代替提供方 id。登录后，此步骤会说明它选择的默认模型：输出上限最大者优先，其次是上下文最大者，因为一份转写稿就是一个很长的回答。
3. 转写工具 —— 基于设置页读取的同一份诊断报告的检查清单：先是 NotebookLM，然后是必需工具及其就地安装按钮，可选工具折叠起来。设置页的列表加详情布局不适合设置页面。
4. 资料库——工作区里有什么，然后进入资料库。

## 考虑过的替代方案

**通过部署补丁配置各步骤。** 否决：浏览器插件收不到行配置（`__DSH_BOOT__` 只携带 id 和 URL）；位置改由登记表得出。

**由一个设置包导入其他包的组件。** 否决：功能插件不得相互导入值；每个包注册自己的步骤，界面通过插槽交互。

**只在会话为空白时保持序列激活。** 否决：登录会保存默认模型，这可能使当前会话不再空白，协调器因此在账户步骤之后丢掉了其余步骤。已开始的序列现在会一直运行到最后一步。

## 后果

第一个画面属于产品本身，使用产品的颜色和语言。注册步骤较少的部署也能正确显示进度。
