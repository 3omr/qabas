# Agent Note: 无会话讲座管理器引擎编辑

Status: implemented

[English](2026-10-02-lecture-manager-wiring.md) | 中文

## 问题

资料库讲座管理器需要在不创建聊天 Session 的情况下管理学生自定义讲座与本地文件。浏览器选取的录音大小为 15–70 MB，必须以 Host 路径交给引擎，失败导入不得遗留暂存文件。

## 决策

转写引擎拥有七个无会话注册表 Remote。它们验证引擎 JSON、传递取消、保留类型化拒绝，并为学生触发的操作传递 `confirmed: true`。模块 id 解析到已存在且受目录包含限制的模块根目录；文件参数拒绝路径遍历。列表验证保留手动讲座 id、来源、资料名称及模块题库状态。这扩展了[无会话工作区决策](./2026-10-01-transcriber-library-workspace.zh.md)，不替代其清单或转写文件写入策略。

浏览器导入通过 unary HTTP 传输规范 base64。Connection 默认 300 MiB 请求体上限可容纳 base64 扩展后的 70 MiB 录音。可配置的 128 MiB 导入上限限制接受的内容；部署须为 base64 和 RPC 信封设置足够的 HTTP 请求体上限。独占且仅所有者可访问的操作系统暂存文件保留原扩展名供引擎转换，并在成功、引擎拒绝或取消后删除。

仅当全部 Remote 方法均存在时，资料库才通过 Cordis effect 注册编辑适配器。引擎文件结果转换为模块相对路径；清单使用首个所属讲座，未知 NotebookLM 存在状态视为 false。NotebookLM 上传尚未就绪时显示页面错误，不计为完成。

## 考虑过的替代方案

**Session 范围的附件上传。** 它需要聊天生命周期，且不会导入选定引擎模块或更新其讲座注册表。

**分块注册表接收。** 现有 HTTP 上限可在单条消息中容纳支持的录音大小。上传 id 和 append/commit/abort 状态会引入保留的 Host 生命周期，而传输并无此需求。

**浏览器直接复制文件。** Python 注册表拥有媒体转换、冲突策略、引用更新及回收站移动；绕过它会重复实现这些规则。

## 后果

导入在内存中保留浏览器编码文件和 Host 解码字节；它有大小限制，但不是流式传输。提高导入上限需要匹配的 Connection 请求体上限及充足内存。引擎取消无法撤销已提交的注册表编辑。Fake-MCP 测试覆盖全部方法、结果验证、路径遍历拒绝、暂存清理、取消及 70 MiB 导入。适配器和插件测试覆盖映射、失败结果、就绪状态及 effect 销毁。不产生模型请求或 Session 事件；真实 NotebookLM 上传仍需手动集成验证。
