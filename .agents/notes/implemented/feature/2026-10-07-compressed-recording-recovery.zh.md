# Agent Note：压缩录音上传与失败来源恢复

Status: implemented

[English](2026-10-07-compressed-recording-recovery.md) | 中文

## 问题

失败的 NotebookLM 音频来源与本地原始录音同名。将所有未就绪来源视为处理中会阻止重新上传，让讲座任务停留在资料准备阶段。较大的原始文件也增加上传时间。

## 决策

[引擎](../../../../engine/README.md)区分终止状态 `error`/`failed` 与处理中状态。经过授权的讲座任务在所有匹配来源都失败时上传新副本，确认其就绪后，仅删除与原始文件完全同名的失败来源。就绪或处理中来源防止重复上传。原始文件保持不变。

FFmpeg 是可安装的必需工具。录音上传在加锁私有缓存中生成单声道 AAC 副本，缓存键包含原始 SHA-256 和编码配置。完整性元数据在复用前验证原始与编码后的字节。原子发布和受控子进程取消防止缓存出现不完整输出。编码副本更大时仍上传较小的原始文件。码率、采样率和压缩超时通过配置校验。`TRANSCRIBER_CONFIG_PATH` 指定持久化 JSON 文件的绝对路径，子引擎继承该设置，包括桌面冻结构建；无效的显式配置文件会在上传前失败。

应用分别显示本地化的压缩、上传与 NotebookLM 处理步骤。压缩只改变音频编码，不裁剪录音或覆盖原始文件。NotebookLM 处理与服务配额仍可能暂停讲座，并允许继续。

## 考虑过的替代方案

**轮询已经失败的来源。** 该状态不会变为就绪，会浪费讲座恢复预算。

**用压缩音频替换原始文件。** 学生失去原始录音质量。

**在替换前删除失败的远程来源。** 上传失败时将没有远程副本。清理在替换成功后进行。

## 影响

应用能在无需学生干预的情况下恢复失败上传，同时保留原始文件并避免重复上传处理中的来源。FFmpeg 可用性属于就绪条件。语音编码以音质换取上传体积，原始文件仍可使用。来源名称与 ID 限制清理范围，不删除无关远程来源。
