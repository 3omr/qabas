# Agent Note: Google 轨迹转移与持久化模型排除

Status: implemented

[English](2026-10-02-model-switch-signatures.md) | 中文

## Problem

Gemini 在模型切换时拒绝未签名的函数调用历史。思考签名属于生成它的模型，而已退役的目录条目可能以 HTTP 404 拒绝回退请求。服务器重启也可能忘记每日额度耗尽状态，再消耗一次请求重新发现它。

## Decision

适配器在 pi-ai 转换后的最终请求 hook 中补全 Google 函数调用签名。pi-ai 0.85.1 删除跨模型签名，并拒绝非 base64 签名；因此将 Google 文档中的 skip_thought_signature_validator 占位值放入 replay 元数据，会在发送前丢失它。hook 补全未签名的函数调用部分，并保留有效的同模型签名。持久化内容和 replay 元数据保持不变。这适用于每个 Google 请求，包括回退和用户更换模型，也适用于 Vertex 的对应请求 hook。

恢复监听器为 HTTP 404 以及明确指出模型不可用或不存在的诊断记录 MODEL_UNAVAILABLE，然后遵循现有回退资格和固定选择规则继续已接纳步骤。不可用条目不会自动过期。每日记录保留提供方重置时区和下一个本地重置日期；比较使用日历日期，因此 Pacific 夏令时不会变成固定的 24 小时额度计时器。

Host storageDomain 在版本 1 的 llm_pi_ai_recovery 中持久化提供方/模型排除记录。恢复在选择前等待加载，并在重试前等待发布。请求监听器停止，活动恢复操作排空后，domain 才关闭。缺少 Host 存储时，最小组合保留进程内行为；存储错误明确失败。记录在进程内跨会话和适配器重新挂载共享。独立服务器进程和提供方别名不进行协调。

## Alternatives considered

复用外部真实签名违反提供方的轨迹归属。修改 node_modules 会让修复在安装后消失。更改持久化 replay 元数据会在用户切回原模型时丢失生成模型的有效签名。将退役模型视为每日额度耗尽，会在每个午夜重试永久不可用条目。仅在内存中保留额度记录，会在重启后重复失败。

## Consequences

转移的函数调用轨迹保留工具标识和结果，但省略生成模型的私有推理状态。对一个账户不可用的目录条目，在此 Host 状态中仍按提供方/模型排除，即使凭据随后更换。部署可以显式删除存储记录以重试该条目。系统不存储凭据。如果所有合格条目都被排除，终止错误列出它们，并区分可重置额度与永久不可用。

每日额度回退 note 仍为固定选择、资格、思考修正和持久化事件归属提供有效依据。本 note 部分取代其仅限进程的持久性及替换模型失败即终止的规定；它不吸收独立的推理修正决策。免费额度请求节拍决策仍适用于分钟额度。

回归测试运行真实 Loader、Agent、pi-ai 转换器和 Google SDK，外部 HTTP fake 拒绝缺失或外部函数调用签名。测试覆盖同模型、模型转移、格式错误签名、额度回退、跳过退役模型及全新模块重启加载。真实 JSON 状态文件证明持久性；额度重置测试覆盖下一个 Pacific 日历日期。现有工具调用截断 fixture 在后续请求前保留纠正结果。随附报告记录实际执行的命令和沙盒限制。
