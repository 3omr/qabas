# Agent Note: 面向学生的名称与资料库展示

Status: implemented

[English](2026-10-11-qabas-student-ui-consistency.md) | 中文

## 问题

阿拉伯语学生会看到同一个撰写者的几个不同名称、技术性的工具标题、顺序被打乱的中英混排文件名、重复显示的未分配资料以及粘连在一起的聊天失败文本。后台刷新会重置资料库的滚动位置。只看凭据的就绪状态忽略了已安装的、使用 Google 登录的聊天适配器，而输入框也不显示由哪个提供方回答。

## 决定

英语界面使用 Omar，阿拉伯语界面使用 عومر。CLI 标识符保留在安装、登录和诊断说明中。两个随产品发布的词典负责工具的人类可读标题和描述；技术标识符放在次要的一行。阿拉伯语编写的文案使用拉丁数字，撰写者检测不再给出精确的时长估计。

资料库渲染器隔离用户提供的名称，并保持数字与单位的顺序。滚动重置取决于路由值，而不是对象身份。聊天把任务提示放在内容区的顶部角落，让输入框和空白首页保持清爽。管理器从未分配列表中排除任何讲座卡片已经显示的文件，包括库存所有权为空、按文件名匹配的资料。引擎的所有权和写入行为不变。

已知的固定引擎说明和缺少考试年份的警告映射到本地化的词典键；未知说明保持原文。终结的聊天错误用 DOM 换行分隔标题和原因。侧边栏在显示缺少密钥的警告之前先检查是否发现了 Omar。一个只读的输入框标签跟随持久化的上次使用的提供方，在第一次请求之前则显示下一次的选择或主机目录的默认值。Gemini 回退会改变该标签，但不会改变已保存的选择。

## 考虑过的替代方案

**为按文件名匹配的资料修改引擎的所有权。** 库存区分明确声明的资料和按标题匹配的撰写输入。在管理器中排除已显示的文件可以保留这一区分，而不改变引擎行为。

**翻译任意的引擎文字。** 只映射已知的固定说明可以保留外部诊断信息，并让新的引擎说明仍然可读，而不需要编造译文。

**重新启用模型选择器。** 学生需要知道由哪个提供方回答，而不是再多一个模型选项。只读标签使用持久化的请求数据和现有的主机目录操作。

**按固定的输入框高度估算来定位任务提示。** 空白聊天的布局和窄宽度会改变输入框的位置。单独的顶部角落避免了这种估算。

## 后果

Vitest 覆盖双向文本属性、文件大小顺序、刷新时的滚动、任务提示的位置、手动和自动的讲座所有权、失败分隔符、说明的本地化、缺少密钥提示的可见性以及提供方回退。由所有者维护的快照固定了英语和阿拉伯语的输出。产品界面只有 en/ar 词典；包文档保留英语/中文配对。提供方逻辑和引擎行为都没有改变。

任务提示位置的断言覆盖了 CSS 规则和 DOM 类；窄和宽两种浏览器布局在实时预览中检查。

## 验证

针对性的 Vitest 覆盖改动的资料库、聊天和设置包。界面文案检查接受 en/ar 词典，客户端包检查接受所有客户端包，构建、hygiene 和文档检查全部通过。
