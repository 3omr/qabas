# Agent Note: 有界的试卷提取与增量发布

Status: implemented

[English](2026-10-10-exam-index-bounded-extraction.md) | 中文

## 问题

大量小规模的 agy 调用占据了考试索引的大部分时间。题量密集的题库即使输入能放进模型，也可能耗尽输出容量或时间：一次 24000 字符的真实运行索引了两份试卷，但一个密集题库在 600 秒后超时。固定的桌面端总截止时间可能丢弃已发布的结果，即使大部分试卷的批次已经在缓存中验证完毕。

## 决定

引擎 JSON 设置 `exam_index_batch_chars` 和 `exam_index_workers` 解析为正整数，默认值分别为 12000 个源字符和三个工作者。源单元保持不可拆分，前后五个相邻单元保留其上下文角色。由一个协调者负责原子化的缓存写入，并按来源和批次位置组装题目；工作者只负责请求和验证批次。每个提交的任务继承截止时间上下文并共享一个本地取消事件。关闭时会设置该事件、取消排队任务，并等待正在运行的子进程树清理完毕。

完成的试卷通过现有的发布锁、来源列表检查、原件哈希检查、已准备单元检查和修复延续进行发布。全部失败的构建会保留之前的发布结果。缓存除了来源指纹和批次数之外还记录源字符预算。缺少该字段的缓存记录会失效，因为旧预算包含每个单元的额外开销；批次数相同并不能证明边界相同。提示词版本保持为 2，因为提取指令和验证都没有变化。超时、输出上限/截断诊断或不可用的 JSON 响应会抛出容量专用的错误；格式错误的提案 JSON 会先经过现有的修复尝试。协调者把核心单元一分为二，原子化地保存拆分决定，并在同一个池中调度两半。递归的后代每侧最多保留五个上下文单元。单单元叶子上的容量失败只会让该试卷失败；认证和证据验证错误不会拆分。

根缓存键保留从零开始的批次索引，例如 `0`。后代追加从一开始的半段位置：`0/1`、`0/2`、`0/1/2`。拆分节点存储 `{"split": true}`；已验证的叶子存储其现有的载荷记录。重试时沿着保存的拆分节点进行，不再请求父批次，并重新验证缓存的叶子。结果先按数字化的根/拆分位置组装，再进行整份试卷的覆盖检查和发布检查。进度保留原来的部分数，并在每一层追加 `split 1/2` 或 `split 2/2`。

MCP 索引在所属请求的作用域内运行，并发出现有的进度通知。主机在终止并回收 MCP 进程之前会先发送取消。`examIndexTimeoutMs` 是索引构建的 3600000 毫秒无进展时限；已完成批次或试卷的进度会重置它。`examIndexOverallTimeoutMs` 提供经过验证的 21600000 毫秒总上限。单个文件的准备仍保留其总截止时间。

## 考虑过的替代方案

- 只降低字符预算无法限制题目数量或由此产生的 JSON 输出；自适应拆分则针对观察到的响应失败作出反应。
- 只增大批次会让多试卷提取保持串行，也无法在中断时保留已发布的工作。
- 每份试卷独立的池会成倍增加进程限制，并让缓存所有权变复杂。
- 工作者写缓存需要在共享的读-改-写状态上加锁，并可能覆盖已验证的结果。
- 在任意 stdout 输出时重置截止时间，会让无关输出掩盖停滞的提取；只有匹配的 MCP 进度通知才会重置无进展计时。

## 后果

固定延迟的假进程基准测试在一个工作者时为 1.869 秒、三个工作者时为 0.672 秒（2.78 倍），覆盖三份各有三个批次的试卷，比较并发与串行的索引，逐份发布试卷，并验证仅用缓存的重试。一个取消测试检查每个正在运行的假子进程都被回收。被中断的构建会保留已完成的试卷，重试时只请求未完成的试卷。主机测试覆盖进度重置、无进展超时、总上限和调用方取消。验证不使用真实的提供方调用，也不修改资料库。超过两个必需单元就模拟容量失败的假实现验证了递归完成、输出顺序不变、上下文重叠以及仅用缓存的重试。一个始终失败的单个单元验证了试卷隔离以及其成功兄弟批次的复用。预算改变时需要重新提取；单个超大的源单元可以超过预算，以保留其定位信息。
