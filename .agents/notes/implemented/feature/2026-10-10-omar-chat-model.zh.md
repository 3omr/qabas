# Agent Note: 学生聊天使用 Omar CLI 模型

Status: implemented

[English](2026-10-10-omar-chat-model.md) | 中文

## 问题

学生默认的聊天助手需要使用其 Google 登录，而不消耗 Gemini API 密钥配额，同时保留 Qabas 的工具权限和持久化的工具历史。CLI 启动所需的时间远长于模型推理，而终结性的账户故障需要一条可用的可选恢复路径。

## 决定

llm-agy 包注册 agy LLM 路由。每个请求都会把记录在日志中的系统文本、对话块和工具模式确定性地渲染成仅供模型使用的提示词。Antigravity 在一个只包含 prompt.md 的私有工作目录中以结构化 JSON 输出和沙箱模式运行；`-p` 参数让它读取该文件，因为带工具模式的聊天提示词超过了命令行参数的限制（Linux 上单个参数 128 KiB，Windows 上整个命令行约 32 KiB）。Qabas 在输出任何内容之前验证每个返回的工具名称和对象参数，然后通过自己现有的循环执行被接受的调用。

共享的子进程所有者负责解析并启动可执行文件，拥有其进程树，并在清理私有目录之前确认进程已退出。配置包含首选模型、推理强度、总时长超时、终止宽限期、输出大小以及可选的 Google 回退。连接重置和资格检查错误使用暂时性的 TRANSPORT 代码；未安装、未登录和配额故障各有不同的终结性 AGY 代码。

条件式配置只在学生没有选择时保存已安装的首选 Omar 模型，包括引导过程中的安装报告。Omar 缺失时，Google 密钥配置仍然可用。终结性的 agy 可用性故障可以在每轮对话中切换一次到已配置的 Google Flash 路由，前提是保存了 Gemini 密钥。现有的 Agent 回退策略授权这次切换，现有的 llm/model-fallback 事件记录其路由和原因，供本地化的聊天提示使用。固定选择的模型会阻止切换。

## 考虑过的替代方案

**由 Antigravity 执行它自己的工具。** 所有者否决了这个方案，因为 Qabas 资料库和引擎的操作必须由 Qabas 记录并控制权限。

**继续把 Gemini API 密钥作为必需的默认项。** 所有者否决了这个方案，因为学生已经有 Google 登录，普通聊天不应该需要 API 密钥配额。密钥仍作为可选的恢复凭据。

**单独的回退对话记录路径。** 现有的模型回退事件和对话节点已经表示同一步骤内的模型切换，平行的机制会重复持久化的恢复语义。

## 相关决定

[每日配额回退的决定](2026-10-02-daily-quota-model-fallback.zh.md)对 pi-ai 的同一提供方内恢复仍然有效。Omar 的跨提供方切换有明确的部署许可，并要求学生保存了 Gemini 密钥；它不改变其他提供方的恢复。引擎在 Windows 上的安装以及讲座撰写的决定仍各自独立负责。

## 后果

学生在英语界面中看到 Omar、在阿拉伯语界面中看到 عومر 作为聊天提供方，Gemini 作为可选回退。提供方的输出会缓冲到 CLI 完成为止。固定的说明和 JSON 框架会增加输入 token；不复用 CLI 的对话持久化。Antigravity 内部对禁用工具说明的遵守、真实的登录行为、模型可用性、Windows 上的发现以及长提示词的命令行长度限制仍需在真实 CLI 上检查。

## 验证

适配器使用不联网的假 CLI 夹具测试文本、工具、嵌套围栏 JSON、无效调用、暂时性错误、终结性的登录和配额错误、目录解析，以及 CLI 及其子进程的取消。基于 Loader 的 Agent 测试覆盖记录在日志中的 Google 切换、缺失的密钥、固定的选择和禁用的回退。配置测试保留学生的明确选择。

无需密钥的录制会话用例 `omar-google-fallback` 通过随产品发布的恢复钩子记录跨提供方的切换。它通过 headless 配置文件重放。真实 CLI 的登录、目录可用性、工具限制以及 Windows 进程树的行为需要实际检查。
