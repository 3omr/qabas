# Agent Note：资料库是应用的第一个画面

Status: implemented

[English](2026-10-01-library-first-shell.md) | 中文

## 问题

Qabas 打开时是一个空白对话。学生拥有的一切——模块、讲座、每节讲座的进度、已完成的转写稿——只能通过询问对话获得，或通过两个不完整的讲座选择器（右侧边栏标签页和输入框上方的条带）查看；它们把同样的讲座列了两遍，既不能打开讲座，也不能开始转写。问一句"还有哪些讲座没转写"就要发起一次模型请求、消耗约 1.5 万个 token，而工作区本身就能回答这个问题。

## 决定

新的客户端插件 [ui-library](../../../../packages/client/ui-library/README.zh.md) 在布局的 `main` 插槽中注册 `library` 键，并在启动时选中它（`startupPanel`，默认 `library`）。它的页面——首页、模块页、讲座页——来自转写引擎的 `list_modules` 和 `list_lectures`；这两个调用无需会话，并报告每节讲座的状态（未开始、原话已取回、草稿、已完成）和文件路径。模块树填充 [ui-sidebar](../../../../packages/client/ui-sidebar/README.zh.md) 在工作区浏览器上方新声明的 `sidebar.library` 插槽。

资料库绘制它自己并不执行的操作。`ctx.library.registerAction` 以 id 为键，因此本包自带的备用操作——在 `transcriber` 代理预设上打开对话并发送一句话——可以被后台运行器替换，而无需改动页面。`registerOpener` 让文件查看器决定转写稿在哪里打开。

对话本身不变，并且一键可达：会话列表、新建会话，以及每个页面上的"问助手"。

## 考虑过的替代方案

**保留对话作为首页，只改进选择器。** 否决：选择器只能部分回答"进度如何"，而且每个操作仍需输入一句话；学生明确希望对话成为次要入口。

**通过 workspace-files Remote 读取工作区。** 否决：它的每次调用都需要会话作用域，而资料库是没有会话的根面板。引擎已经定义了什么是一节讲座，再读一遍就会把规则放到第三个地方。

**把资料库做成右侧边栏标签页。** 否决：标签页受会话约束并与对话分享宽度，而资料库是主要界面。

## 后果

应用的第一个画面不发起任何模型请求。一旦没有其他依赖，重复的讲座选择器就可以移除。后续界面（后台任务、转写稿编辑器、首次设置）接入 `ctx.library`，而不是接入对话。
