# Agent Note: 配额排除记录跟随密钥

Status: implemented

[English](2026-10-04-quota-exclusions-follow-the-key.md) | 中文

## Problem

恢复记录按提供方与模型标识，因此 Gemini 每日配额排除记录在替换已耗尽账户的密钥后仍然存在。有效的新密钥可能在请求到达 Google 之前失败。已学习的每分钟预算与冷却时间也可能属于旧账户。

## Decision

Settings 凭据控制器在成功保存与移除后等待串行 `credentials/reference-reset` 事件，包括替换与重复保存。Gemini 目录检查返回 `works` 时等待同一重置；失败与配额检查保留恢复记录。事件仅携带带品牌的引用名，不携带密钥或哈希。

pi-ai 监听器将引用映射到配置了对应 `apiKeyEnv` 的路由；Google profile 没有显式引用时，也映射到 Google 原生的 `GEMINI_API_KEY` 认证。这包括 Settings 卡片的 `google: {}` profile 与休眠的 Google 路由。恢复重置按需打开 Host 域，再清除内存与 `llm_pi_ai_recovery` 域中的每日记录。存储不可用时，存储组件保留清除操作，后续加载会删除提供方的旧每日记录，而不会恢复它们。存储写入与重置串行执行。节拍器忘记受影响路由所有模型的预算、预约与冷却时间。其他提供方、模型不可用记录与成功的思考修正保留。

进程内重置版本使待处理的轮次覆盖失效，并阻止迟到的旧密钥响应或排队写入恢复配额记录。计数器不含凭据信息，无需更改持久化格式。插件释放时监听器与请求恢复一起等待工作结束。重置失败在凭据写入提交后向调用方抛出，不能撤销已保存的密钥。

## Alternatives considered

**使用现有更新通知。** 更新观察者不被等待，且会包含失败。已完成的保存可能与持久化清除竞争，或掩盖其失败。显式串行事件保留现有通知行为。

**持久化凭据指纹。** 哈希归属能区分并发账户，但需要在请求接纳、恢复与持久化记录中传递凭据身份。按提供方清除能清理旧排除记录，无需保留从凭据派生的标识。

**删除全部恢复记录。** 模型不可用与思考修正描述模型。更换密钥不会使其失效；清除其他提供方还会忘记无关账户的限制。

## Consequences

新的生成请求可能再次发现配额耗尽。目录检查成功不能证明剩余生成配额。重置覆盖控制器操作；直接调用凭据提供方写入、外部文件编辑与环境变量变化不会调用此事件。独立进程保留各自的速率知识。

[每日模型回退](../feature/2026-10-02-daily-quota-model-fallback.zh.md)、[免费层节拍控制](../feature/2026-10-02-free-tier-rate-limits.zh.md)与[认证密钥检查](../feature/2026-10-03-lecture-visibility-and-key-checks.zh.md)决策保留其独立的路由、节拍与认证依据。本记录负责凭据失效处理；这些决策均未被完全取代。

使用假 HTTP 的 Agent 回归测试覆盖保存、替换、移除、成功与失败检查，以及迟到的旧密钥配额响应。Loader 回归测试涵盖重启后 Web Host 的原生 Google 路由、兄弟 Settings Controller 插件，以及 pi-ai 先于存储加载的顺序。已提交实现没有将原生 Google 认证映射到重置，因此无法通过这些重启回归测试。恢复存储测试使用临时存储，覆盖仅内存运行、加载、排队写入与重启后的持久化删除。节拍器测试保留其他提供方的限制。验证结果与沙箱限制记录在实现报告中。
