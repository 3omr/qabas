# Agent Note: 整份试卷范围内的考试年份出处

Status: implemented

[English](2026-10-10-exam-year-provenance.md) | 中文

## 问题

印在试卷页眉中的考试日期可能不在某道题引用的单元或提取批次之内。只按题目单元验证会拒绝该日期，而模型省略年份时又会丢弃可信的文件名出处。把扫描文件名中的日期与另一个不同的印刷考试日期合并，还会把单份考试误判为题库。

## 决定

每个来源快照保留所有来源单元的规范化文本。年份证据要求包含完整匹配的年份词元，且规范化后的短语逐字出现在该文本中，或者是已有的可信文件名年份。出现记录把 `year_source` 记为 `question`、`paper` 或 `filename`；无法确定的年份记为 null。

单一年份的往年考试会为缺失或被拒绝的题目年份补上年份：先取第一个有据题干之前文本中的年份，若文本没有给出冲突年份，再取文件名中的年份。印刷的页眉年份优先于文件名出处。文本或文件名中出现多个年份，或明确标为题库，都禁止整体赋值。已有的题目复核原因在回退赋值后仍保留，但回退本身不要求复核。讲座查询会按来源字节重新验证每个出现记录；当年份印在该出现记录之前的来源单元中时，`paper` 年份即可通过，因此后续页面上的题目会保留页眉年份，而不会被当作未验证而丢弃。

讲座验证和修复接受由讲座评估目录中某个来源的任何有试卷依据的索引出现记录所携带的 `**[Past Exams - YYYY]**` 徽章年份，无论其 `year_source` 为何。试卷依据已经会丢弃来源文本不支持其年份的出现记录，因此题库在题目所在行或分区之外的汇编年份仍被拒绝。在此之前只有 `owner` 索引年份有效，而电子表格题库的 `question` 年份无法由任何文本解析器从工作表导出文本中恢复，因此虽然 `verify_provenance` 接受同样的徽章，`validate_draft` 却会失败。

文件名与页眉不一致时，只在该来源的 `review_reasons` 中出现一次，并为 `needs_review` 增加一项来源级复核。来源的 `years` 保留已赋予的题目年份，并使用印刷的试卷年份而不是冲突的扫描文件名年份。提示词和 schema 版本保持不变，因为缓存的原始批次载荷会按当前的后处理规则重新验证。

## 考虑过的替代方案

**只用题目单元作为证据。** 拒绝页眉证据会让有效的印刷日期无法进入索引，并使题目结果依赖于批次的划分位置。

**无条件使用文件名回退。** 在印刷考试日期不同的情况下仍采用扫描日期会丢失考试出处；把一个年份赋给题库会把无日期的题目归到错误的考试。

**在每道题上重复不一致复核。** 这种不一致只关乎一个来源，并不说明每道题的措辞或答案存在不确定性。

## 后果

页眉证据可以跨批次验证，而无需重复构建整份试卷的文本。模型缺失年份时，仍可保留站得住的出处，而不引入题目复核标记。页眉回退是保守的：它要求能精确定位规范化的题干，并且在最早的题干之前只有一个印刷年份；页眉和文件名出处都不满足时，来源保留 null 年份。试卷任意位置出现多个年份词元都会禁用整体赋值，即使其中一个只是偶然出现。

回归测试覆盖其行年份能验证讲座徽章的已索引 `.xlsx` 题库、阿拉伯数字、冲突的扫描日期、被省略和被拒绝的模型年份、多年份题库、缺失证据、缓存载荷重放，以及位于提取批次之外的页眉证据。这个仅限引擎的改动不会修改或重新运行真实的资料库来源。
